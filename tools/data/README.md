# ข้อมูลหลังบ้าน (source of truth)

โฟลเดอร์นี้คือแหล่งข้อมูลจริงของเว็บ — แก้ที่นี่แล้วรัน `tools/build_data.py`
หนึ่งครั้ง ไฟล์ที่เว็บโหลด (`assets/data/app-data.js`) จะถูกสร้างใหม่ให้

| ไฟล์ | เก็บอะไร |
|---|---|
| `songs.csv` | เพลง: รหัส ชื่อ ธีมสี BPM และจำนวนบีตเริ่มต้นของเฟรม |
| `lyrics.csv` | เนื้อเพลงทีละบรรทัด (1-based) |
| `frames.csv` | เฟรมของแต่ละเพลง: ชื่อ คิว Insight จำนวนบีต และบรรทัดเนื้อเพลง |
| `grids.csv` | ผังสี 15 × 10 ของทุกเฟรม (10 แถวต่อเฟรม) |
| `extras.json` | ข้อมูลนอกเหนือรายเพลง: สี แสตน ใบเพลง โปรแกรม อุปกรณ์ คำผิด |

> **อย่าแก้ `assets/data/app-data.js` ด้วยมือ** — ไฟล์นั้นถูกเขียนทับทุกครั้งที่ build

## เปิดด้วย Excel / Google Sheets

1. เปิดไฟล์ `.csv` ด้วย Excel
2. แก้ข้อมูล
3. บันทึกเป็น **CSV UTF-8 (Comma delimited)**
   — ถ้าเลือก CSV ธรรมดา ภาษาไทยจะเพี้ยน
4. คอลัมน์ที่มี `1-2-3-4`, `00:`, `#` หรือข้อความยาว ๆ ให้จัดรูปแบบเป็น **Text**
   ก่อนวาง ไม่งั้น Excel อาจแปลงเป็นวันที่/เวลา

Notepad / VS Code ก็แก้ได้ (ไฟล์เป็น UTF-8 มี BOM สำหรับ Excel)

## `songs.csv`

```csv
song_id,code,show_code,title,subtitle,bpm,default_beats,theme_a,theme_b,file,raw_blocks,notation,desc
1,2,2,ขึ้นมือ G,...,180,16,#7030a0,#ffc000,1_ขึ้นมือ G.html,9,"...","..."
```

| คอลัมน์ | ความหมาย |
|---|---|
| `song_id` | identity ถาวร ใช้กับ `#song=N`, `songbook.pageId` — **ห้ามสลับ/เรียงใหม่** |
| `code` | รหัสเพลงที่แสดงผล เช่น `2`, `14–15` |
| `show_code` | รหัสบนป้ายแสดง (ปกติเท่ากับ `code`) |
| `bpm` | จังหวะเพลงจริง; ว่าง = 180; ช่วงที่รับ 40–240 |
| `default_beats` | จำนวนบีตต่อเฟรมเมื่อ `frames.csv` ไม่ได้ระบุ; ว่าง = 16 |
| `theme_a`, `theme_b` | สีไล่ระดับของ UI (`#rrggbb`) ไม่ต้องอยู่ใน palette |
| `file` | ชื่อไฟล์ต้นฉบับ (เก็บไว้เป็นข้อมูล ไม่ได้ใช้ runtime) |
| `raw_blocks` | ค่าเดิมจากใบเพลง (ไม่เท่ากับจำนวนเฟรม) — เว้นว่างได้ |
| `notation`, `desc` | ข้อความอธิบาย |

**เว้น `bpm` / `default_beats` ว่าง = ใช้ 180 / 16** ซึ่งทำให้เฟรมละ 5.3 วินาที

## `lyrics.csv`

```csv
song_id,line_no,text
1,1,ตึง ตึง ตึง 1 · ...
```

- `line_no` เป็น **1-based** และต้องเรียงต่อเนื่อง `1..N` ต่อเพลง
- ถ้าแทรกบรรทัดกลางเพลง บรรทัดของเฟรมถัดไปจะเลื่อน — ตรวจ `lyric_line` ใน `frames.csv` ด้วย

## `frames.csv`

```csv
song_id,frame_no,code,name,cue,insight,beats,lyric_line,lyric_highlight
1,1,1.1,ต้นไม้ 4 สี + อักษร G,"ก้ม 4 ขึ้น 8","ฝั่งซ้ายใช้ 4 เฉด",16,1,
1,7,1.7,อักษร HELLO,"สะบัดค้าง","HELLO เขียวอ่อน 53 ช่อง",16,3,เชียร์
```

| คอลัมน์ | ความหมาย |
|---|---|
| `frame_no` | ลำดับเฟรม 1..N ต่อเพลง (ห้ามข้าม/ซ้ำ) |
| `code` | รหัสเฟรม; เว้นว่าง = `song_id.frame_no`; ถ้าใส่ต้องไม่ซ้ำทั้งงาน |
| `beats` | จำนวนบีตของเฟรมนี้; เว้นว่าง = ใช้ `default_beats` ของเพลง; รับ 1–128 |
| `lyric_line` | เลขบรรทัดเนื้อเพลง 1-based; เว้นว่างหรือ `-1` = เฟรมบรรเลง |
| `lyric_highlight` | คำที่ต้องไฮไลต์ คั่นด้วย `|` เช่น `เชียร์|สวัสดี` ต้องเป็นข้อความจริงในบรรทัดนั้น |

### ไฮไลต์เฉพาะครั้งที่ต้องการ

ถ้าคำนั้นปรากฏหลายครั้งในบรรทัด ให้เติม `#` หลังคำ:

| ตัวอย่าง | ไฮไลต์ |
|---|---|
| `พิริยาลัย` | **ครั้งแรก**เท่านั้น (ค่าเริ่มต้น) |
| `พิริยาลัย#2` | ครั้งที่ 2 |
| `พิริยาลัย#1-3` | ครั้งที่ 1–3 |
| `พิริยาลัย#2,4` | ครั้งที่ 2 และ 4 |
| `พิริยาลัย#all` | ทุกครั้ง |

ใช้ร่วมกับ `|` ได้ เช่น `พิริ|ยาลัย#2` — และ build จะตรวจให้ว่าเลขครั้งที่ระบุ
ไม่เกินจำนวนที่พบจริงในบรรทัดนั้น

ระยะเวลาเฟรม = `beats × 60000 / bpm` มิลลิวินาที
เช่น 16 บีตที่ 180 BPM = 5.3 วินาที

## `grids.csv`

หนึ่งแถว = หนึ่งแถวของผัง; หนึ่งเฟรมมี 10 แถว

```csv
song_id,frame_no,row_no,A,B,C,D,E,F,G,H,I,J,K,L,M,N,O
1,1,10,0,0,0,2,2,0,0,0,0,6,6,6,6,6,6
1,1,9,0,0,0,2,2,0,0,0,0,6,6,6,6,6,6
```

- `row_no` คือเลขแถวบนใบเพลง: `10` บนสุด → `1` ล่างสุด
- ช่องละ **1 ตัวอักษร** จาก palette ด้านล่าง (ตัวพิมพ์เล็ก)
- ช่องว่างถือเป็นขาว (`0`) แต่ build จะเตือนเพื่อไม่ให้ซ่อนความผิดพลาด

| รหัส | สี | รหัส | สี |
|---|---|---|---|
| `0` | ขาว `#ffffff` | `a` | เขียว `#6aa84f` |
| `1` | ดำ `#000000` | `b` | เขียวเข้ม `#548235` |
| `2` | แดง `#ff0000` | `c` | แดงเข้ม `#cc0000` |
| `3` | เขียว `#00ff00` | `d` | ฟ้า `#00ffff` |
| `4` | เหลือง `#ffff00` | `e` | ม่วง `#9900ff` |
| `5` | ชมพู `#ff00ff` | `f` | ม่วงอ่อน `#9933ff` |
| `6` | ม่วง `#7030a0` | `g` | ส้ม `#ff9900` |
| `7` | น้ำเงิน `#0000ff` | `h` | เหลืองทอง `#f1c232` |
| `8` | แดงเลือดหมู `#980000` | `i` | เทา `#999999` |
| `9` | ส้มเหลือง `#ffc000` | `j` | เทาอ่อน `#b7b7b7` |
|   |   | `k` | สะบัดมือ `#d9ead3` |

## `extras.json`

เก็บ `meta`, `colors`, `show`, `songbook`, `program`, `equipment`, `typos`
พร้อมฟิลด์ช่วยแก้ข้อมูล (ไม่ถูกส่งออกไปเว็บ):

- `songbook` entry ที่ใช้เนื้อเพลงเดียวกับเพลงหลัก → ใช้ `"lyricsRef": song_id`
  build จะเติม `lyrics` ให้อัตโนมัติ
- entry ที่ชี้เฟรมเดียว → ใช้ `"stepCode": "9.1"` build จะแปลงเป็น `stepIndex`
- `sheetImport` เก็บชื่อไฟล์/ลำดับ block เดิมไว้เผื่อ import จาก HTML ในอนาคต
- `program` เป็นรายการแสดงแยกจาก `songs.csv` — ถ้า `code` ตรงกันแต่ชื่อไม่ตรง
  build จะเตือน (ไม่แก้ให้อัตโนมัติ) เพราะบางช่วงใช้ชื่อย่อตั้งใจ

## เพิ่ม/แทรกเฟรม

1. เพิ่มแถวใน `frames.csv` โดยใช้ `frame_no` ใหม่ แล้วเรียงเลข `frame_no` ของเฟรมหลังจุดแทรกใหม่ให้ต่อเนื่อง
2. เพิ่ม 10 แถวใน `grids.csv` ด้วย `song_id` + `frame_no` เดียวกัน และ `row_no` 10→1
3. ถ้า `songbook` มี `stepCode` ชี้เฟรมที่เลื่อน build จะ error บอกให้แก้
4. รัน build — ถ้า `beats` เว้นว่าง เฟรมใหม่ใช้ `default_beats` ของเพลง

## เพิ่มเพลง

1. ต่อท้าย `songs.csv` ด้วย `song_id` ใหม่ (ไม่ต้องเรียง id ให้ต่อจากเพลงสุดท้ายจริง ๆ ได้ แต่ต้องไม่ซ้ำ)
2. เพิ่ม `lyrics.csv`, `frames.csv`, `grids.csv` ของเพลงนั้น
3. ถ้าต้องการให้ใบเพลง/program อ้างถึง ให้แก้ `extras.json`
4. build จะเรียงเพลงตาม `song_id` ให้เอง

ไม่ต้องแก้ Python หรือ JavaScript

## ปรับ BPM / ความถี่ของเฟรม

1. เปิด `tools/tap-tempo.html` ในเบราว์เซอร์ เปิดเพลงจริง แล้วแตะตามจังหวะ 8–16 ครั้ง
2. ใส่ BPM ที่ได้ใน `songs.csv`
3. เลือก `default_beats`:
   - **16** = ค่ากลาง (5.3 วินาที/เฟรมที่ 180 BPM) — แนะนำ
   - **8** = เปลี่ยนท่าถี่ขึ้น (4 วินาที)
   - **24–32** = ท่าค้างนาน/ช่วงบรรเลง
4. ถ้าเฉพาะบางช่วงต่างจากเพลง ให้ใส่ `beats` รายเฟรมใน `frames.csv`
5. รัน build แล้วดู `tools/out/timing-report.csv`
   — มี `frame_ms`, `start_mmss`, `duration_s` ของทุกเฟรม

สูตรคิดจากความยาวเพลงจริง:

```text
default_beats ≈ round((seconds × bpm) / (60 × frames) / 4) × 4
beats ของช่วงหนึ่ง ≈ round((เวลาช่วงนั้น × bpm) / 60)
```

build จะเตือนถ้าเฟรมสั้นกว่า 1 วินาที หรือยาวกว่า 16 วินาที

## Build / deploy

```bash
# ตรวจอย่างเดียว
python3 tools/build_data.py --check

# สร้างจริง + bump ?v= ใน index.html
python3 tools/build_data.py

# index.html เป็น bind mount ไฟล์เดี่ยว ต้อง restart container
docker compose restart web
```

ถ้าข้อมูลผิด build จะพิมพ์ `ไฟล์:บรรทัด` เป็นภาษาไทยและ **ไม่เขียนไฟล์**
แก้ตามนั้นแล้วรันใหม่

ไฟล์ที่สร้าง:

- `assets/data/app-data.js` — bundle ที่เว็บโหลด
- `tools/out/timing-report.csv` — ตารางเวลาต่อเฟรม (ไม่ commit)

## ข้อควรระวัง

- `song_id` และ `code` ถูกอ้างจาก `#song=`, `songbook.pageId`, `stepCode`
  — เปลี่ยนแล้ว build จะฟ้องถ้าอ้างถึงไม่ได้
- การแทรกเฟรมกลางเพลงต้องเรียง `frame_no` ใหม่ทั้งช่วงหลังจุดแทรก
- Excel อาจเติม `"` หรือแปลงเลข `1-2-3` เป็นวันที่ — ตรวจหลังบันทึกทุกครั้ง
- ถ้าไม่ bump `?v=` หน้าเว็บอาจโหลด JS เก่าปนกับข้อมูลใหม่ (build ทำให้อัตโนมัติ)
